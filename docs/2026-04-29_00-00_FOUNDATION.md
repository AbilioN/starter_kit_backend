# Foundation — What Was Built Before Tier 1
**Created:** 2026-04-29  
**Purpose:** Single source of truth for everything that existed before the Tier 1 build session. Written for future agents starting cold.

---

## Project Identity

Originally called "Addresses Dashboard", now evolved into a **BtoB backend starter kit**.  
Stack: **Laravel 12 / PHP 8.2**, **MySQL 8** (runtime), **SQLite** (tests), **Redis**, **Docker**, **Pusher** (WebSockets).

- Admin client → **Nuxt** (separate repo)
- User client → **Flutter** (separate repo)
- This repo is **API-only**, no frontend assets

Base URL: `http://localhost:8006/api`

---

## Architecture (Non-Negotiable)

```
Presentation   app/Http/Controllers, Requests, Middleware, routes/
Application    app/Application/UseCases, DTOs, Services (Eloquent→Domain bridges)
Domain         app/Domain/Entities, Repositories (interfaces), Services (interfaces), Exceptions
Infrastructure app/Infrastructure/Repositories, Services (Eloquent/DB implementations)
Models         app/Models  (Eloquent only — no business logic)
```

**Rules:**
- Controllers call Use Cases only
- Use Cases depend on Domain interfaces only (never Eloquent)
- Infrastructure implements interfaces, touches Eloquent freely
- Repositories return **domain entities**, never DTOs
- DTOs are created inside entities via `toDto()` and used only in Application/Presentation

Service container bindings live in `app/Providers/DomainServiceProvider.php`.  
`AppServiceProvider` handles bootstrapping only (broadcasting, Horizon auth gate).

## What Was Built (Pre-Tier 1)

### 1. User Authentication

**Routes:** public, no middleware  
**Models:** `app/Models/User.php` — uses `HasApiTokens`, `Notifiable`, `HasAuditLog`

| Endpoint | Controller | Notes |
|---|---|---|
| `POST /login` | `Api/Auth/LoginController` | Returns `{user, token}` |
| `POST /register` | `Api/Auth/RegisterController` | Sends email verification code |
| `POST /verify-email` | `Api/Auth/VerifyEmailController` | Activates account |
| `POST /resend-verification-code` | `Api/Auth/ResendVerificationCodeController` | |

**Email verification flow:** register → code stored in `email_verifications` table → user submits code → verified.

Response shape for login:
```json
{ "user": { "id": 1, "name": "...", "email": "...", "email_verified_at": "..." }, "token": "..." }
```

### 2. Admin Authentication

**Routes:** `/api/admin/login`, `/api/admin/register` — public  
**Models:** `app/Models/Admin.php` — uses `HasApiTokens`, `Notifiable`, `HasAuditLog`  
**Middleware:** `admin.auth` — checks `is_active` flag after Sanctum resolves the user

| Endpoint | Notes |
|---|---|
| `POST /api/admin/login` | Returns `{admin, token, roles}` |
| `POST /api/admin/register` | Creates non-super-admin |

**AdminFactory** (`app/Application/Services/AdminFactory.php`) is the canonical bridge: converts the Eloquent `Admin` model to a `Domain\Entities\Admin` entity for use in use cases and authorization checks.

```php
$admin = AdminFactory::createFromModel($request->user());
```

---

### 3. RBAC — Roles & Permissions

**Tables:** `roles`, `permissions`, `role_permissions`, `admin_roles`  
**Permission slug format:** `<resource>-<action>` e.g. `admin-read`, `role-manage`, `audit-read`

**Authorization pattern in every admin controller:**
```php
$admin = AdminFactory::createFromModel($request->user());
$this->authorizeActionUseCase->execute($admin, 'permission-slug');
// throws 403 with { "message": "..." } if denied
```

Super admins bypass all permission checks automatically.

**Seeded roles:** `super-admin`, `admin`, `manager`, `viewer`  
**Seeded permissions (pre-Tier 1):**

| Resource | Actions |
|---|---|
| `admin` | create, read, update, delete, manage |
| `user` | create, read, update, delete |
| `chat` | read, manage |
| `role` | create, read, update, delete, manage, assign, unassign |
| `audit` | read (only — immutable by design) |

**Seed order for tests:**
```php
$this->seed(RoleSeeder::class);
$this->seed(PermissionSeeder::class);
$this->seed(AdminSeeder::class);
$this->seed(AdminRolePermissionSeeder::class);
```

### 6. Chat System (Real-Time)

**The only feature-domain fully hand-authored before Tier 1.**  
Broadcasting via **Pusher**. All routes require `auth:sanctum`.

**Tables:** `chats`, `messages`, `chat_user` (pivot with `user_type`)

**Important:** Source of truth for participant type is `chat_user.user_type`, not `messages.sender_type` (removed).

**Routes:**
```
POST /chat/create-private               — find or create private chat between two users
POST /chat/create-group                 — create group chat with participants
POST /chat/{chatId}/send                — send message (returns 202 Accepted, queued)
GET  /chat/{chatId}/messages            — get messages (sender_type derived from chat_user)
POST /chat/{chatId}/read                — mark messages read
GET  /chat/{chatId}/unread-count        — unread badge
GET  /chat/conversation/{userId}/{type} — get or create conversation
GET  /chats                             — list all chats for authenticated user
POST /broadcasting/auth                 — Pusher channel auth
```

**Chat types:** `private`, `group`  
**Participant types:** `admin`, `user` (both can participate in same chat)

**Env needed:**
```
PUSHER_APP_ID=
PUSHER_APP_KEY=
PUSHER_APP_SECRET=
PUSHER_APP_CLUSTER=
BROADCAST_CONNECTION=pusher
```

### 7. Audit System (Immutable)

**Design:** audit logs are IMMUTABLE. No delete or update endpoints exist, not even for super admin. This is by design for LGPD/GDPR compliance.

**Auto-logging via trait:** Add `HasAuditLog` to any Eloquent model and `created`/`updated`/`deleted` are logged automatically.

**Models using the trait:** `Admin`, `User`, `Role`, `Permission`

**Table:** `audit_logs`  
Fields: `user_id`, `user_type`, `action`, `model_type`, `model_id`, `old_values`, `new_values`, `description`, `ip_address`, `user_agent`, `url`, `method`, `tags`, `metadata`

**Routes** (all require `audit-read` permission):
```
GET /api/admin/audit                        — list with filters
GET /api/admin/audit/{id}                   — single log
GET /api/admin/audit/model/{type}/{id}      — history of a model
GET /api/admin/audit/user/{type}/{id}       — activity of a user
GET /api/admin/audit/action/{action}        — by action type
GET /api/admin/audit/tag/{tag}              — by tag
```

**Filter query params:** `user_id`, `user_type`, `model_type`, `model_id`, `action`, `tags`, `date_from`, `date_to`

**Manual audit:**
```php
$useCase = app(LogAuditUseCase::class);
$useCase->execute(userId: ..., userType: 'Admin', action: 'custom_action', modelType: User::class, modelId: 5, description: '...', tags: ['security']);
```

## HTTP Response Conventions

| Situation | Status | Shape |
|---|---|---|
| Successful read/update | 200 | `{ "success": true, "data": ... }` |
| Resource created | 201 | `{ "success": true, "data": ... }` |
| Async / queued | 202 | `{ "success": true, ... }` |
| Unauthenticated | 401 | `{ "message": "..." }` |
| Permission denied | 403 | `{ "message": "..." }` |
| Validation error | 422 | `{ "message": "...", "errors": {...} }` |

Auth endpoints return `{ user: ..., token: ... }` or `{ admin: ..., token: ..., roles: [...] }` — no `success` key.

## Testing Conventions

- Feature tests: `tests/Feature/` — HTTP-level, uses `RefreshDatabase`
- Unit tests: `tests/Unit/`
- DB for tests: SQLite at `/var/www/storage/app/sqlite/testing.sqlite` (phpunit.xml)
- Standard setUp:
  ```php
  $this->seed(RoleSeeder::class);
  $this->seed(PermissionSeeder::class);
  $this->seed(AdminSeeder::class);
  $this->seed(AdminRolePermissionSeeder::class);
  ```
- Permission denial test pattern: remove permission from role, assert 403 with exact error string
- Use `assertJsonStructure()` and `assertJsonPath()` for API assertions

## Known Quirks

- There are three chat controllers in the codebase (`Api/Chat/ChatController`, `Api/ChatController`, `Api/Admin/ChatController`). Only `Api/Chat/ChatController` is wired in `routes/api.php`.
- `AdminFactory` is the single canonical bridge admin model → domain entity. Never instantiate `Domain\Entities\Admin` directly in controllers.
- `SettingRepository` is registered as a **singleton** (Tier 1) for cache consistency within a request.
